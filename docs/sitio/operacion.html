Laboratorio y despliegue

Cómo levantar el sistema en tu equipo, cargar datos de prueba, verificar contratos, resolver los problemas más comunes y entender las compuertas de calidad de la integración continua.

infra.ps1 Docker por secciones Escenarios CI y compuertas Conventional Commits

Todo se ejecuta desde la raíz del workspace con el ayudante maestro .\AsistenciasUCO-Infra\infra.ps1. Guías de origen: AsistenciasUCO-Infra/docs/runbooks/PRUEBAS_LOCALES.md, DEMO_DOCKER.md y AsistenciasUCO-Infra/stack/README.md.

Escenarios y memoria

El laboratorio completo no cabe en la máquina virtual de Docker (límite de 9700 MB, %USERPROFILE%\.wslconfig con 10 GB). Por eso se levanta por secciones o por escenarios. asis-datos es la única sección con reinicio automático.

EscenarioSeccionesMemoriaPruebas que cubre
minimoasis-datos2,5 GBGate de BD y scripts SQL
basicodatos, seguridad, notificaciones, app5,75 GBHU de los 5 roles
mensajesbásico + mensajes9,05 GBCatálogo de mensajes y textos UI
parametrosbásico + parámetros6,35 GBCatálogo de Parámetros y su microfrontend
completobásico + mensajes + parámetros9,65 GB de 9,7 GBFlujos con los tres componentes (no agregar más secciones)
soportesbásico + antivirus7,05 GBAdjuntos de reclamos con MinIO y ClamAV
observabilidadbásico + obs6,65 GBTrazas, métricas y logs por correlationId
contingenciadatos, contingencia, notificaciones, app5,05 GBArranque con el Keycloak propio
  • ext-mensajes y ext-parametros requieren ext-seguridad; ext-notificaciones requiere asis-datos. Se agregan solas.
  • asis-contingencia y ext-parametros no pueden convivir: ambos usan el puerto 8081 del PC.
  • Con asis-app, stack up genera la configuración del backend y del frontend (stack/generado/*.env, fuera de Git) según lo que esté arriba. Por ejemplo usa el proveedor baseline con ext-seguridad y el legacy con la contingencia.

Aprovisionar el PDP (permisos de rutas)

Cada endpoint del backend debe estar concedido a sus roles en el PDP. Una ruta nueva sin concesión responde 403 aunque el código esté bien.

PasoComandoEfecto
1python -X utf8 -I GestioAsistenciaBackend/infra/security-baseline/scripts/provision_asistencias.py verifyCompara el PDP con access-catalog.json. Las líneas FALTA indican concesiones ausentes.
2... provision_asistencias.py pdpAgrega lo que falta. Es aditivo.
3... provision_asistencias.py verify-decisionsPrueba la decisión real PEP a PDP por endpoint y rol.
Nunca --prune en la demo Revoca lo que el catálogo no declara. Su ejecución en el PDP compartido la hace el dueño del componente (decisión DEC-071). stack up y datos-prueba ya aprovisionan de forma aditiva; se omite con -SinPdp.

Solución de problemas

SíntomaCausa y solución
403 en una ruta o endpoint nuevoEl PDP no tiene la concesión. stack up y datos-prueba ya la corrigen; manual: provision_asistencias.py pdp y luego verify. Nunca --prune.
Contenedores que mueren o stack up rechaza por memoriaDocker sin memoria. Sube .wslconfig a 10 GB o detén secciones que no uses con stack down <sección>. Antes del gate de BD detén MessageUcoLab, Kong, el Catálogo y ClamAV.
Error engine.sock o docker colgadoReinicia Docker Desktop (wsl --shutdown y ábrelo de nuevo) y verifica con docker ps.
datos-prueba cargar pide definir PythonDefine ASISTENCIAS_PYTHON con la ruta de python.exe. El alias de la Microsoft Store y el Python de MSYS se descartan.
Falta la imagen asistencias-backend:developEjecuta infra.ps1 stack build.
Error de collation al desplegar el esquemaLa base debe crearse con la collation del esquema. Usa datos-prueba cargar -Yes (recrea desde cero) en vez de restaurar una base de otro servidor.
Hay un backend local en el puerto 8080Deténlo o usa datos-prueba cargar -Yes -StopBackend.
La sesión «se cae» durante la demoEs esperado: el token de acceso dura 5 minutos (se renueva por PKCE) y la sesión SSO 30 minutos.
Frontend sin estilos o en blancoTras un stack build, recrea la app con stack up asis-app -Conservar.
migrar.ps1 -Modo Aplicar re-ejecuta todoCon dbo.MigracionAplicada vacía, las migraciones desde la 05 figuran pendientes. Corre siempre antes migrar.ps1 -Modo Estado (solo lee).
Orden de migraciones Aplica las migraciones antes que deploy_schema.ps1 (TD-081): algunas recrean procedimientos con el texto de su época y, con otro orden, pisan objetos más nuevos.

Integración continua y compuertas

Cada repositorio tiene su flujo de GitHub Actions. Un PR a develop debe pasar todas las compuertas.

Backendbackend-ci.ymlmvn clean verify: pruebas unitarias, ArchUnit, empaquetado y reporte JaCoCo; análisis de calidad.
integration.ymlmvn verify -Pintegration contra una BD desplegada con el mismo script del CI de BD.

security-deep-scan.ymlArchUnit, Trivy sobre el repositorio y sobre la imagen de producción.
load-test.ymlPrueba de carga de lectura con k6 (manual).

Convenciones de commits y ramas

Los commits siguen Conventional Commits 1.0.0, en español y en modo imperativo. Cada capa tiene su commit atómico: no se mezclan BD, backend y frontend en un solo paquete.

ElementoReglaEjemplo
Estructura<tipo>(<alcance>): <descripción>, primera línea de 72 caracteres como máximo, sin punto finalfix(db/sp): corregir evaluacion de inasistencia en usp_calcular_perdidas
Tiposfeat, fix, refactor, test, perf, docs, ci, chorerefactor(backend/adapter): retirar plantillas, renderizado y SMTP del backend
Alcancesdb/sp, db/tables, db/views, backend/controller, backend/usecase, backend/adapter, frontend/realtime, frontend/docente, scripts, docs, entre otrostest(frontend): agregar cobertura realtime
Cuerpo y pieObligatorios en cambios de arquitectura o de HU: qué cambió, por qué y cómo. El pie referencia la HU (Refs: HU043) y los cambios incompatibles (BREAKING CHANGE:)Refs: HU043
  • Nunca se relajan ni se desactivan pruebas para que pasen: se corrige el código de producción, salvo que la prueba tenga un error técnico real o un cambio formal de contrato.
  • Antes de empujar una rama, comprueba que el PR no esté ya mezclado.
  • Un cambio de contrato exige addendum, hash nuevo y infra.ps1 verify en verde.
