## Diseño

1. Sin default: `${app.security.azure-events.webhook-token:}` y `webhook-token: ${AZURE_EVENTGRID_WEBHOOK_TOKEN:}` (vacío ⇒ 401 fail-closed).
2. Header único `aeg-sas-token`; se elimina todo query parameter.
3. Comparación de digests SHA-256 con `MessageDigest.isEqual` (JDK, sin dependencias).
4. Path exacto (sin context path) compartido por filtro y matcher CSRF (`AzureEventGridAuthFilter.isWebhookRequest`).
5. `AzureCloudIntegrationIT` (solo lectura, endpoints por entorno, falla sin ambiente); `integration` lo excluye; perfil `azure-integration` ejecuta solo `*CloudIntegrationIT` sin Surefire ni JaCoCo.

## Rollback

Revertir el diff de la fase (sin migraciones ni contratos). Operativamente, definir `AZURE_EVENTGRID_WEBHOOK_TOKEN` en el ambiente y configurar el header `aeg-sas-token` en la suscripción Event Grid antes de desplegar; sin ello el webhook responde 401.

## Riesgos

- Despliegues que dependían del default o del query token dejarán de autenticar (intencional). Acción operativa: definir la variable y usar el header. No se documentan valores.
- El handshake exige la credencial (política actual). Si Azure real exigiera otra cosa: `CONTRACT/OPERATIONAL_CONFLICT`; no observado en esta fase (Event Grid real NOT_RUN).
