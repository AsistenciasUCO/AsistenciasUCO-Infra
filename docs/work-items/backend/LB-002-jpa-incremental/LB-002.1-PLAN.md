## Alcance

- Dependencia `spring-boot-starter-data-jpa` (versión administrada por Spring Boot 4.0.6 → Hibernate 7.2.12.Final).
- Modelo JPA de solo lectura de las vistas `uv_detalle_asistencia`, `uv_asistencia`, `uv_estudiante_grupo`.
- Implementación JPA (HQL) de la query y selector `app.adapters.persistence.asistencia-query-provider` (`jdbc` default | `jpa`).
- Adapter híbrido: query → JPA; commands → JDBC.
- Paridad real JDBC vs JPA contra SQL Server, ArchUnit de aislamiento JPA.

## No alcance / rutas prohibidas

Application (puertos, use cases), Domain, controllers, OpenAPI, frontend, DB (repo DB solo lectura; sin git, scripts ni DDL/DML), `uv_auth_*`, `SESSION_CONTEXT`, `usp_consultar_grupos_paginado`/paginación, migración de commands/SP, retiro de JDBC, provider default JPA.

## Diseño (ver [DECISION](LB-002.1-DECISION.md))

Selector solo en Composition Root; `EntityManagerFactory` explícito y condicional (auto-configuración JPA de Boot excluida); un único `AsistenciaRepositoryPort`; una sola invocación por provider (sin dual-read en runtime).

## Evidencia y validación

RED → GREEN → `verify` normal (hermético) → `-Pintegration verify` contra la DB real → paridad campo a campo. Detalle en [TEST-PLAN](LB-002.1-TEST-PLAN.md), [PARITY](LB-002.1-PARITY.md) y [VALIDATION](LB-002.1-VALIDATION.md).

## Riesgos y rollback

Riesgos: tipado de UUID/boolean/null en Hibernate+SQL Server (mitigado por paridad real), N+1 (medido con Hibernate Statistics solo en IT), autoconfig JPA rompiendo el default (excluida y verificada). Rollback: `asistencia-query-provider=jdbc` (sin rollback de DB/API/frontend/datos).

## Stop conditions

Ninguna se activó (schema/OpenAPI/puertos/use cases/dominio sin cambios; sin `uv_auth_*`/`SESSION_CONTEXT`/paginación; paridad 0 mismatches; N+1 no aparece; sin ambigüedad de beans; hashes intactos; `origin/sergio` sin cambios).
