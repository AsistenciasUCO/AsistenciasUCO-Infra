# LB-004B.2 — IMPLEMENTATION

Resumen del GREEN implementado después de [LB-004B.2-RED-SNAPSHOT](LB-004B.2-RED-SNAPSHOT.md), sobre
el contrato de [MINIO_STORAGE_CONTRACT](MINIO_STORAGE_CONTRACT.md) / [CONTENT_SECURITY](CONTENT_SECURITY.md).

## Application (neutral, sin SDK de infraestructura)

- `application/secondaryports/storage/FileStoragePort.java` — `store/read/exists/delete`,
  `StoredObjectMetadata` neutral, excepciones propias (`StorageException`,
  `StorageUnavailableException`, `ObjectNotFoundException`).
- `application/secondaryports/malwarescan/MalwareScanPort.java` — `scan(byte[]) -> ScanResult`;
  `MalwareScanException` para fail-closed.
- `application/features/archivo/shared/contentsecurity/` — `ContentSecurityValidator` (tamaño,
  extensión, MIME declarado, magic bytes, sanitización de nombre), `CompressionPolicy` (evaluación con umbral
  10%, DEFLATE vía `java.util.zip`, sin dependencia nueva), `ChecksumCalculator` (SHA-256).
- `application/features/archivo/subirarchivo/**` — `SubirArchivoInputPort` /
  `SubirArchivoUseCase` / `SubirArchivoUseCaseImpl` (orquesta validación → scan fail-closed →
  compresión → checksum → store) / `SubirArchivoResultadoEntity` (usecase-layer, mapeado a
  `SubirArchivoResultado` DTO por el Interactor — requerido por `CleanArchitectureRulesTest`:
  `usecase` no depende de `primaryports.dto`).
- `application/features/archivo/descargararchivo/**` — mismo patrón; `DescargarArchivoUseCaseImpl`
  aplica ownership técnico fail-closed (`ownerSubject` debe igualar al `requesterSubject`; cualquier
  otro actor → `ResourceNotFoundException`, 404) y descomprime transparentemente si aplica.

## Infrastructure

- `infrastructure/adapter/secondary/storage/minio/MinioFileStorageAdapter.java` — único
  componente que conoce `io.minio.MinioClient`; objectKey `soportes/<fileId>`; metadata técnica
  como user metadata S3; traduce excepciones del SDK.
- `infrastructure/adapter/secondary/malwarescan/clamav/ClamAvMalwareScanAdapter.java` — cliente
  minimalista del protocolo clamd/INSTREAM sobre `Socket`/`DataOutputStream` (sin dependencia de
  terceros no auditada); fail-closed ante cualquier `IOException`/respuesta inesperada.
- `infrastructure/config/properties/providers/MinioProviderProperties.java` /
  `ClamAvProviderProperties.java` — fail-fast (`IllegalStateException`) si falta configuración
  obligatoria; credenciales MinIO solo por variable de entorno.
- `infrastructure/config/adapters/storage/minio/MinioStorageAdapterConfiguration.java` —
  Composition Root, `@ConditionalOnProperty(app.adapters.storage.provider=minio, matchIfMissing=true)`.
- `infrastructure/config/adapters/malwarescan/clamav/ClamAvMalwareScanAdapterConfiguration.java` —
  Composition Root sin selector (ClamAV es el único provider aprobado).
- `infrastructure/config/wiring/ArchivoWiringConfiguration.java` — ensambla UseCase+Interactor
  para ambas features, siguiendo el patrón de `AsistenciaWiringConfiguration`.
- `infrastructure/config/properties/adapters/StorageAdapterProperties.java` — `Provider` pasa de
  `{LOCAL}` a `{MINIO}`; ya no hay fallback local (decisión humana, ver `PROFESSOR_DECISION.md`).
- `infrastructure/adapter/primary/controller/archivo/ArchivoController.java` — refactorizado para
  depender exclusivamente de `SubirArchivoInputPort`/`DescargarArchivoInputPort`/
  `AuthenticatedUserResolver`; cero `Files`/`Paths`; `owner`/`requester` siempre de la identidad
  JWT, nunca de un campo de request; `GET /{fileId}` usa `UUID`, malformado → `ResourceNotFoundException`
  (404, nunca 400, para no distinguir formato de existencia).
- `infrastructure/config/security/SecurityConfig.java` — `POST /api/v1/archivos/subir` ahora
  exige rol `ESTUDIANTE` (antes: `authenticated()` genérico, cualquier rol); `GET
  /api/v1/archivos/{fileId}` permanece bajo el catch-all `authenticated()` porque el ownership
  real (incluida la postura `DENY_BY_DEFAULT` para docente/coordinador/administrador) se resuelve
  en Application, no en Layer 1.

## Configuración / infraestructura local

- `pom.xml` — `io.minio:minio:9.0.3` + `com.squareup.okhttp3:okhttp-jvm:5.3.2` explícito (ver nota
  técnica abajo).
- `application.yml` — `spring.servlet.multipart.max-file-size=5MB` (= 5 MiB exactos en
  `DataSize` de Spring), `max-request-size=6MB`, `file-size-threshold=5MB`;
  `app.providers.minio.*` / `app.providers.clamav.*`;
  `app.adapters.storage.provider` default cambia de `local` a `minio`.
- `infra/files/compose.yaml` — servicios `minio` (Community compilado desde source upstream fijado,
  ver `MINIO_STORAGE_CONTRACT.md`/`RISKS.md R-LB004-024`), `minio-init`, policy test y `clamav`
  (`clamav/clamav:1.5.4-debian13-slim` por digest), con healthcheck y volumen Docker
  dedicado que NO se monta en el backend.
- `.env.example` del backend contiene únicamente la identidad técnica de aplicación.
  `infra/files/.env.example` separa root/bootstrap de aplicación; root nunca llega a Spring Boot.

## Hardening LB-004B.2H

- `ArchivoController -> SubirArchivoDTO -> SubirArchivoDomain -> ContentSecurityValidator` propaga
  `declaredContentType`; extensión, MIME declarado y magic bytes deben ser coherentes.
- ClamAV infectado conserva 400 controlado; indisponibilidad/timeout/protocolo inválido produce el
  error técnico estándar seguro (500), sin convertir un fallo de infraestructura en archivo inválido.
- `DescargarArchivoUseCaseImpl` recalcula SHA-256 después de descomprimir y falla cerrado ante
  mismatch antes de construir la respuesta.
- `FileStoragePort.delete` permanece capability interna; no existe endpoint DELETE público.

## Nota técnica: okhttp 5.x y MinIO SDK 9.0.3

`io.minio:minio:9.0.3` declara `com.squareup.okhttp3:okhttp:5.3.2`, pero en okhttp 5.x ese artefacto
es un shim vacío (reestructuración Kotlin Multiplatform): las clases JVM reales (p. ej. `HttpUrl`)
viven en `com.squareup.okhttp3:okhttp-jvm`. Sin declarar esa dependencia explícita, la compilación
fallaba (`cannot access okhttp3.HttpUrl`) porque el proyecto ya trae transitivamente
`okhttp-jvm:5.2.1` (vía `opentelemetry-exporter-sender-okhttp`), una versión distinta a la que
`minio` espera. Se fijó `okhttp-jvm:5.3.2` explícito para alinear versiones.

## ArchUnit nuevo

`StorageProviderIsolationRulesTest` — Controller/Application no dependen del SDK MinIO ni de
filesystem directo; solo `MinioFileStorageAdapter` conoce `io.minio.*` entre los adapters; solo
`ClamAvMalwareScanAdapter` conoce el cliente socket clamd entre los adapters (el Composition Root
queda fuera de esta restricción a propósito: construir el adapter es su trabajo).

## Desvío de Clean Architecture corregido durante GREEN

El primer intento de `SubirArchivoUseCase`/`DescargarArchivoUseCase` retornaba directamente el DTO
de `primaryports.dto` (`SubirArchivoResultado`/`DescargarArchivoResultado`). `CleanArchitectureRulesTest.
usecase_no_depende_de_primaryports_dto` (ya existente, no creado por esta tarea) lo detectó
correctamente. Se corrigió introduciendo `usecase/entity/SubirArchivoResultadoEntity` /
`DescargarArchivoResultadoEntity` (resultado interno del UseCase) y moviendo el mapeo a DTO al
Interactor vía el Mapper — exactamente el patrón ya usado por
`ConsultarAsistenciasPorGrupoUseCase`/`AsistenciaConsultadaEntity`. No se tocó ni se debilitó la
regla ArchUnit.
