- `GET /swagger-ui/index.html` y assets locales se sirven desde recursos empaquetados.

## Riesgos y dependencias

- Exponer el WebJar por su handler automático crearía una UI alternativa aun con la property
  deshabilitada. Mitigación: desempaquetar assets en build sin incluir el WebJar como dependencia
  runtime y registrarlos solo mediante un handler condicional.
- Un handler estático global ignoraría la property. Mitigación: recursos fuera de las ubicaciones
  estáticas por defecto y `@ConditionalOnProperty`.
- Un initializer inline exigiría relajar CSP. Mitigación: JavaScript externo versionado; no se
  cambian headers globales.
- La copia runtime podría divergir. Mitigación: copia determinística sin filtering y comparación
  HTTP byte-for-byte/SHA contra el canónico.
- Dependencia de build: `org.webjars:swagger-ui:5.32.15`, Apache-2.0, sin dependencias transitivas;
  requiere descarga Maven para la primera construcción.

## Stop conditions

- La librería genera OpenAPI o requiere `/v3/api-docs`, CDN, annotations o cambios de controllers.
- Incompatibilidad demostrada con Spring Boot 4.0.6/Java 25/OpenAPI 3.1.2.
- Es necesario relajar seguridad/CSP/CORS global o abrir `/api/**`.
- Cambia el SHA canónico, aparece segunda spec editable o el runtime no es byte-identical.
- `CONTRACT_CONFLICT`, `TEST_CONTRACT_CONFLICT` o `BLOCKED_BY_MISSING_EVIDENCE` relevante.
