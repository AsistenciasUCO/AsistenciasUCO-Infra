# DECISION — LB-001C.3: estrategia Swagger UI runtime

## Matriz de alternativas

| STRATEGY | RUNTIME DEPENDENCY | SPRING BOOT 4 COMPATIBILITY | GENERATES SECOND OPENAPI? | CANONICAL YAML DIRECT? | SECURITY IMPACT | MAINTENANCE | DECISION |
|---|---|---|---|---|---|---|---|
| A. Swagger UI WebJar/static assets + YAML copiado en build | Ninguna librería Java runtime; assets `org.webjars:swagger-ui:5.32.15` empaquetados en build | PASS: archivos estáticos + `WebMvcConfigurer`; Boot 4 soporta MVC/WebJars y Java 25 | NO | YES | Handler condicional; GET docs `permitAll`; API sin cambios | Versión explícita y dos archivos de configuración pequeños | **SELECTED** |
| B. `springdoc` usado solo como UI externa y generación deshabilitada | Starter runtime y auto-configuración Spring | No demostrada para la combinación exacta sin introducir superficie extra | Riesgo de `/v3/api-docs`/auto-config | Sí, configurable | Más beans/endpoints y flags de desactivación | Mayor acoplamiento/version skew | REJECTED |
| C. UI propia/otro framework o CDN | Variable; puede añadir Node/plantillas/runtime | Sin ventaja demostrada | Variable | Variable | Riesgo de CORS/CSP/CDN | Mayor código propio | REJECTED |

## Decisión

Se selecciona A con una variante de menor acoplamiento: Maven desempaqueta únicamente los assets
de Swagger UI durante `process-resources`; el WebJar no se incluye como dependencia runtime. El
YAML canónico se copia sin filtering desde `docs/contracts/openapi/openapi-golden-path.yaml` al
output de build. Un `WebMvcConfigurer` condicionado por `asistencias.swagger-ui.enabled=true`
publica ambos conjuntos de recursos.

No existe generador OpenAPI, `/v3/api-docs`, annotation scanner ni segunda spec editable. El
initializer usa exactamente `/openapi/openapi-golden-path.yaml`.

## Evidencia de compatibilidad

- El proyecto usa Spring Boot 4.0.6 y Java 25; el gate base `mvn -B -ntp verify` pasó con 987/987.
- La documentación oficial de Spring Boot 4 describe soporte de recursos estáticos/WebJars y
  extensiones MVC mediante `WebMvcConfigurer` sin `@EnableWebMvc`.
- Swagger UI declara que la línea 5.32 soporta OpenAPI 3.1.2; Maven Central publica el WebJar
  5.32.15 sin dependencias transitivas.
- La compatibilidad efectiva se cierra con compilación, tests MockMvc y arranque local del mismo
  artefacto en Spring Boot 4.0.6/Java 25.

Fuentes consultadas:

- https://github.com/swagger-api/swagger-ui#compatibility
- https://central.sonatype.com/artifact/org.webjars/swagger-ui/5.32.15
- https://docs.spring.io/spring-boot/reference/web/servlet.html
- https://docs.spring.io/spring-boot/system-requirements.html

## Consecuencias

- El runtime queda desacoplado de swagger-core/springdoc y no puede generar un contrato paralelo.
- El build necesita resolver el WebJar una vez; el servidor y navegador funcionan sin Internet.
- Actualizar Swagger UI requiere coordinar la property Maven y la ubicación classpath explícita,
  y revalidar assets/UI/OpenAPI; este acoplamiento acotado evita añadir un locator runtime.
- Deshabilitar Swagger elimina handlers UI/YAML sin afectar startup ni `/api/**`.
