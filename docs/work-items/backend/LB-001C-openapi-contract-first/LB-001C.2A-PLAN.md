# LB-001C.2A — Plan (EXPAND compatible PUT → PATCH)

Estrategia: EXPAND → MIGRATE CONSUMERS → VERIFY → RETIRE LEGACY. Esta fase solo hace EXPAND.

## Evidencia AS-IS inspeccionada

- Path real: `/api/v1/sesiones/{sesionId}` (`SesionController`, `@RequestMapping("/api/v1/sesiones")`).
- PUT actual: `SesionController.actualizarSesion` → `SesionHttpMapper.toApplicationDTO` →
  `ActualizarSesionInputPort` → `ActualizarSesionUseCaseImpl` → `SesionRepositoryPort.actualizarSesion`
  (SP en adapter SQL Server). Éxito 200 `ApiDataResponse<Void>` `{exitoso:true,datos:null}`.
- `ActualizarSesionRequest {nombre, fechaHoraInicio, fechaHoraFin}`; OpenAPI los declara los tres `required`,
  `additionalProperties:false` (campos desconocidos → 400 `FIELD_UNKNOWN`). Sin validador HTTP propio;
  el Domain valida nombre (`ERR_NOMBRE_SESION_*`) y fechas; ownership en el use case (403).
- Seguridad: `SecurityConfig` ya autoriza `PUT` y `PATCH` `/api/v1/sesiones/**` con `DOCENTE`; CORS ya permite PATCH.
- Consumidor: frontend documentado usa PUT (MV-001); fuera de alcance.

## Semántica PATCH (decisión)

PATCH modifica la **subrepresentación mutable** de Sesión (`nombre`, `fechaHoraInicio`, `fechaHoraFin`); no
reemplaza `id`, `numero`, `codigo`, `numeroSemana`, `grupo`. Los tres atributos siguen **obligatorios**
(el comando actual los exige); no hay merge campo a campo, ni semántica `null` nueva, ni JSON Patch /
Merge Patch. Media type `application/json`. Mismo schema `ActualizarSesionRequest` (DTO sin cambios).

## Cambios

1. OpenAPI: `patch` `actualizarSesion` (nuevo); `put` → `actualizarSesionLegacy`, `deprecated: true`. SHA regenerado.
2. Tests RED → `LB-001C.2A-RED-SNAPSHOT.md`.
3. Controller: `@PatchMapping` `actualizarSesion` y `@PutMapping` `actualizarSesionLegacy` (`@Deprecated(forRemoval=false)`)
   delegan a un método privado común → mismo input port. Sin cambios en composition root, dominio, DB.

## No alcance / rollback

Sin frontend, DB, Keycloak, JPA, Redis, RabbitMQ, Swagger UI runtime, clientes generados, commit ni push.
Rollback: revertir el `@PatchMapping`, el operation `patch` del YAML y regenerar SHA.
