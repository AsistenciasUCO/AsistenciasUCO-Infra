# REPORT — LB-001C.3: Swagger UI runtime over canonical OpenAPI

## Resultado

**DONE / PASS.** El backend publica una Swagger UI offline y el YAML crudo únicamente cuando
`asistencias.swagger-ui.enabled=true`. La UI consume el contrato canónico byte-for-byte, no existe
generación code-first ni `/v3/api-docs`, y las rutas de negocio conservan JWT/RBAC.

Contrato conservado:

- OpenAPI 3.1.2;
- 9 operaciones: GET 5, POST 2, PATCH 1, PUT legacy/deprecated 1, DELETE 0;
- SHA-256 `72a3097bbae2a296ed6690bf89c239f56697764f25100b930d941a699736da54`;
- PATCH `actualizarSesion` canónico; PUT `actualizarSesionLegacy` aún compatible/deprecated;
- consumidores frontend PUT: 0 según evidencia de entrada C.2 reportada, sin autorizar retiro.

## Estrategia y versión

Se eligió `org.webjars:swagger-ui:5.32.15` como insumo de build, no como dependencia Java runtime.
Maven desempaqueta un conjunto mínimo de assets locales en `process-resources`; otra ejecución
copia el YAML canónico sin filtering. `SwaggerUiConfiguration` registra handlers solo con la
property habilitada.

Razones:

- Swagger UI 5.32 declara compatibilidad con OpenAPI 3.1.2;
- Spring Boot 4 soporta recursos estáticos y extensión MVC mediante `WebMvcConfigurer`;
- evita el acoplamiento y la superficie de auto-configuración de `springdoc`;
- no puede inferir un segundo contrato desde annotations;
- no deja el WebJar accesible por un handler automático cuando la feature está OFF.

Referencias: [Swagger UI compatibility](https://github.com/swagger-api/swagger-ui#compatibility),
[WebJar 5.32.15](https://central.sonatype.com/artifact/org.webjars/swagger-ui/5.32.15),
[Spring Boot servlet web](https://docs.spring.io/spring-boot/reference/web/servlet.html) y
[Spring Boot system requirements](https://docs.spring.io/spring-boot/system-requirements.html).

Riesgos de mantenimiento: la versión del WebJar y la ubicación classpath versionada deben
actualizarse coordinadamente; cada upgrade debe repetir parser, hash, MockMvc y navegador. La UI
muestra un aviso no bloqueante ante el `jsonSchemaDialect` canónico distinto del dialecto base;
esto no cambia la validez OpenAPI ni justifica modificar la fuente contractual.
