## Pruebas RED requeridas

- Nuevos tests runtime esperan UI/YAML/assets/config/property y fallan porque no existen handlers.
- Tests RBAC esperan docs `permitAll` y fallan porque hoy `anyRequest().authenticated()` aplica.
- Los tests existentes de business API/OpenAPI deben permanecer verdes durante el RED.
- El archivo y SHA de tests se congelan antes de modificar `pom.xml` o producción.

## Congelación

La orden humana aprueba las expectations. El implementador no cambia los tests RED; un conflicto
se registra como `TEST_CONTRACT_CONFLICT` y se detiene el alcance afectado.

## Integración y E2E

No requiere DB, frontend ni Keycloak. MockMvc cubre HTTP/config/security. El arranque local y la
inspección en navegador cubren render, assets offline, 9 operaciones, PATCH/PUT y Authorize. No se
ejecutan mutaciones automáticas. SSE se valida con herramienta específica, no con Try It Out.

## Falsos positivos a evitar

- No comparar una copia de test con otra copia generada por el propio test.
- No mockear el handler de recursos ni introducir una spec de test.
- No aceptar solo texto cosmético: el body runtime debe ser byte-identical al canónico.
- No considerar 401/403/404 ambiental como evidencia del render Swagger.
