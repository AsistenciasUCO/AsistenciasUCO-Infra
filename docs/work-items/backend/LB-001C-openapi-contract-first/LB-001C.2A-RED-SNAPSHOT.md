# LB-001C.2A — RED snapshot

Fecha: 2026-09-24. Java 25, `mvn -o test -Dtest='OpenApiGoldenPath*Test,SesionControllerContractTest,RbacSecurityFilterChainTest'`.
Estado: OpenAPI ya declara `PATCH /api/v1/sesiones/{sesionId}` (`actualizarSesion`) y `PUT` como
`actualizarSesionLegacy` `deprecated: true` (SHA regenerado); el controller **aún no expone PATCH**
ni el método `actualizarSesionLegacy`. Sin cambios de producción.

Esperado: PATCH declarado en el contrato; provider sin PATCH.

| Test | Resultado RED | Causa |
|---|---|---|
| `OpenApiGoldenPathConformanceTest.specContainsExactlyTheFrozenGoldenPathControllerMappings` | ERROR NoSuchMethod | provider sin `SesionController.actualizarSesionLegacy` / mapping PATCH |
| `OpenApiGoldenPathConformanceTest.successStatusesAndMediaTypesMatchTheRunningControllerContracts` | FAIL | "El controller no expone actualizarSesionLegacy" (PATCH ausente) |
| `OpenApiGoldenPathConformanceTest.allGoldenPathOperationsDeclareReusableBearerAndCorrelationContracts` | FAIL | idem |
| `SesionControllerContractTest.patchUpdatesSessionThroughSameInputPortWithPathBodyAndActor` | FAIL 200 esperado, 500 obtenido | `PATCH` no mapeado en el controller |
| `SesionControllerContractTest.putLegacyAndPatchProduceIdenticalCommandAndResponse` | FAIL 200 esperado, 500 obtenido | idem |
| `SesionControllerContractTest.patchPreservesValidationBehaviorOfPut` | FAIL 400 esperado, 500 obtenido | idem |

Nota: el 500 proviene de que el `GlobalExceptionHandler` real mapea el método no soportado a
`INTERNAL_ERROR`; se registra tal cual, sin modificarlo (comportamiento preexistente).

Tests GREEN ya en RED por diseño (evidencia de misma autorización, no dependen del controller):
`RbacSecurityFilterChainTest.actualizar_sesion_put_y_patch_*` (403 coordinador, 401 bearer inválido,
DOCENTE permitido) — `SecurityConfig` ya autoriza `PATCH /api/v1/sesiones/**` con `DOCENTE`.

Corrección de expectativa propia: una primera versión del test 401 enviaba la petición sin
Bearer y obtuvo 403 (CSRF, comportamiento existente, ver `post_sin_bearer_y_sin_token_csrf_permanece_bloqueado`);
se ajustó a bearer inválido → 401, alineado con los tests existentes. No es un fallo de producción.
